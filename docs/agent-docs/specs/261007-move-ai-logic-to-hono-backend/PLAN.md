# Plan: Move the mobile app's AI logic into the Hono backend

Status: approved (adversarial-agent, round 2: AGREE)
Spec: SPEC.md (approved: adversarial-agent, round 4: AGREE)

## Approach
The OpenRouter and Borel transport halves of `apps/mobile/src/lib/core/db/ai.ts` move nearly verbatim into a new backend router, `apps/backend/src/routes/ai.ts`, mounted at `/api/ai` in `app.ts` beside the existing routers; the mobile `ai.ts` keeps its entire public surface (`ai.chat`, `ai.transcribe`, `ai.image`, `ai.editImage`, `ai.models` with its two pinned ids, every type export) and becomes a thin client that still does the device-only work (consent with its exact kind selection, image/audio normalization, image-only dedupe, the metered post with the `!reused` predicate, refusal notes on image results) and otherwise POSTs to the backend endpoints with the session cookie replayed exactly as the data client does. The backend owns the API key, the OpenRouter SDK chat transport, the 60s/150s provider timeout budgets, the schema-scoped structured-output retry loop, and all provider-error mapping, returning the same result objects the app resolves today; the image endpoints act as a transparent header-forwarding proxy to Borel. The client owns the 65s/160s request margins and maps transport-level outcomes to the spec's exact sentences. Tests for the moved transport become `bun:test` suites in the backend with `chatSend` and the Borel `fetch` injected and the session resolver swapped for a fake, so no database and no network are needed; the real better-auth gate lives in the DB-gated e2e suite; the mobile suite swaps its transport cases for thin-client cases and gains the AC-11 source check.

## Data Model and Contracts
Request/response JSON at `/api/ai/*` (session cookie required; 401 body `{ "error": "You need to sign in first." }`; everything else answers 200 with the result object):
- `POST /api/ai/chat`: request `{ model?, messages: ChatMessage[], temperature?, max_tokens?, jsonSchema? }` — `ChatMessage` is `{ role: "system"|"user"|"assistant", content: string | (text | image_url | input_audio)[] }` with `image_url`/`input_audio` parts already normalized client-side; unknown body fields ignored; response `AiChatResult` `{ text, data, error, status, reason: null, truncated, raw, detail }`.
- `POST /api/ai/transcribe`: request `{ audio: { data, format? } }` (the client drops `language`/`prompt`); unknown body fields ignored; response `AiTranscribeResult` `{ text, error, status, reason: null, detail }`.
- `POST /api/ai/images/generations`: request `{ prompt, size? }`; `POST /api/ai/images/edits`: request `{ image, prompt, size? }`; unknown body fields ignored; response `{ url, error, status, reason, reused }` — the mobile client strips `reused` before resolving its unchanged `AiImageResult` (`{ url, error, status, reason }`).
- Type ownership: every spec-listed type (`ChatMessage`, `ChatContentPart`, `AiChatResult`, `AiTranscribeResult`, `AiImageResult`, `AiJsonSchema`, `AiImageAsset`, `AiImageInput`, `AiAudioRecording`, `AiAudioInput`) is declared verbatim in both workspaces — the backend router module and the mobile `ai.ts` — with no cross-workspace import; only the backend's image wire response adds `reused`, which the client consumes and strips. There is no database schema change.
- Env contract: backend `OPENROUTER_API_KEY` and `BOREL_AI_URL` (both plain, non-`EXPO_PUBLIC_` names); mobile `EXPO_PUBLIC_BACKEND_URL` unchanged and now also feeding `BACKEND_AI_URL`.

## Quality Gates
Backend `lint`, `typecheck`, `test`, and `build` (`tsconfig.build.json` excludes `*.test.ts` from `dist`); mobile `lint`, `typecheck`, and `test`; the database-backed integration cases skip with the existing reported reason when no `PG*` variables are configured (AC-10).

## Risks
- The Speakeasy-generated `@openrouter/sdk` may import something that misbehaves when imported under Bun rather than Metro/Jest: mitigation is the runtime import smoke check (the real router module is imported by the backend suite, so a bad import fails `bun test`, not just `tsc`), plus the injected `chatSend` seam keeping the transport tests independent of that import. The earlier idea of a plain-`fetch` chat fallback is withdrawn: it would be scope creep against AC-3's `chatSend` mandate.
- Double timeouts (client 65s/160s margins over the backend's 60s/150s provider budgets) could in the worst case hold sockets for long periods: accepted in the spec on purpose; no streaming and no queueing, so load stays bounded by concurrency; Bun's default request-size ceiling comfortably covers the ~4 MB base64 worst case, and the AC-4 cap guard runs server-side before any provider call, which the oversize test asserts (no provider fetch).
- Token/cookie plumbing mistakes would silently 401 every AI call: the e2e authorized case and the thin-client cookie/credentials assertions catch both directions.
- Removing the mobile SDK dependency could break a hidden import: the `transformIgnorePatterns` cleanup, typecheck, and the AC-11 source scan surface any survivor at gate time.
- The two workspaces now hold duplicate type definitions: kept in sync manually, mitigated by the mobile suite asserting the re-exported shapes against the thin-client results, and by the tiny surface (ten named types plus `ai.models`).
