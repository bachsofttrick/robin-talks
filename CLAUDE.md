# Robin Talks

A voice-first English speaking practice app for non-English speakers. Each session
drops the learner into a short, realistic scenario (ordering coffee, asking for
directions, a job interview) where the AI partner Robin plays the other person,
speaks through text-to-speech, listens to the reply, coaches English inline, and
writes a debrief at the end. It is an Expo React Native app that is client-only:
there is no server, API layer, or build step in this repository. Accounts, data,
files, and image generation go through the Borel cloud proxy at `api.borel.one`;
chat and speech-to-text go directly to OpenRouter.

## Tech Stack
- Expo `~57.0.26` with React Native `0.86.3` and React `19.2.3`
- TypeScript `~6.0.3` in `strict` mode (`tsconfig.json`)
- React Navigation 7: native, native-stack, bottom-tabs
- `@neondatabase/neon-js` `^0.7.0-beta` for the Data API and auth client (Supabase-shaped)
- `@openrouter/sdk` `^1.4.18` for chat completions (speech-to-text uses plain `fetch`)
- Jest `~29.7` with the `jest-expo` preset; ESLint 9 flat config via `eslint-config-expo`
- Bun is the package manager (`bun.lock` is present)

## Directory Layout
- `src/` - application source
- `src/lib/api/` - domain hooks and static data (scenarios, profile, sessions, memory, Robin)
- `src/lib/core/` - Borel-managed backend kit (db, auth, legal) split into submodules
- `src/lib/ui/` - shared visual kit and theme tokens
- `src/lib/polyfills/` - runtime shims imported by the entry file before the app
- `src/navigation/` - React Navigation container and root navigator
- `src/screens/` - the four screens: Onboarding, Practice, Session, Settings
- `borel-store.js`, `borel-systemui.js` - vendor bridges generated by Borel (reactive store, native modules)
- `assets/` - app icon, splash, favicon
- `docs/agent-docs/` - this knowledge base, plus specs and plans working artifacts
- `openspec/` - OpenSpec change proposals and synced specs

## Key Commands
- Install: `bun install`
- Test: `bun run test` (Jest, `jest-expo` preset)
- Run: `bun start` (or `bun run ios` / `bun run android` / `bun run web`)
- Lint: `bun run lint` (`eslint .`)
- Typecheck: `bun run typecheck` (`tsc --noEmit`)

## Conventions
- Listen to the entry wiring: `expo-entry.js` imports the polyfills, wraps the app
  in `SafeAreaProvider`, then renders `src/index.tsx`, which nests `ErrorHandler` >
  `StatusBar` > `AppFonts` > `CoreProviders` (`AuthProvider`) > `NavigationContainer`
  > `RootNavigator`.
- Do not hand-edit files whose first line is `// Managed by Borel.`. They are
  `src/lib/core/db.ts`, `src/lib/core/auth.tsx`, `src/lib/core/legal.tsx`,
  `src/index.tsx`, and `src/lib/ui/fonts.tsx`. Both bridge files at the root are
  vendor code too. Put app logic elsewhere.
- `db.ts` and `auth.tsx` are thin connectors: implementation lives in the
  `db/` and `auth/` subfolders, and the top-level file re-exports the public
  surface. Keep that shape when adding code.
- Screens reach data only through the hooks in `src/lib/api/`, never through
  `db` directly (except the AI `transcribe` call in the Session screen). Hooks
  return `{ data, loading, error, ...actions }`.
- Every user-facing error is one plain, non-technical sentence. Use
  `plainError(error, "save" | "load")` for db failures; keep technical text in a
  separate `detail` field.
- Shared state goes through `createStore` from `borel-store.js` (module-scope
  singleton read with `useSyncExternalStore`). React Context is used only for auth.
- Import from the local barrel (`../ui`, `../api`, `../core/db`, `../core/auth`)
  rather than deep paths where a barrel exists.
- Never store raw audio. Only the transcript and debrief reach the database.
- OpenSpec drives specs and changes under `openspec/`; the `docs/agent-docs/specs/`
  and `docs/agent-docs/plans/` folders hold sdd/pdd working artifacts.
